## 请求链路

```mermaid
sequenceDiagram
    participant C as Client (grpcurl / 前端)
    participant L as LoggingLayer
    participant S as SaTokenGrpcLayer
    participant H as gRPC Handler
    participant SV as Service / Repo
    participant DB as MySQL

    C->>L: gRPC 请求
    L->>S: 记录耗时
    S->>S: PathAuthConfig 判定公开/受保护
    S->>H: 注入 SaTokenLoginId
    H->>SV: 调用 CrudService
    SV->>DB: SQLx 查询
    DB-->>SV: 行数据
    SV-->>H: FieldMap
    H-->>C: typed data（code=1000）
```

## crate 分层

```text
cool-admin-rust/
├── proto/                  # 共享契约（common.v1 / internal.v1）
├── crates/                 # 基础库（可复用）
│   ├── cool-proto/         #   proto 代码生成（聚合各 app 自有 proto）
│   ├── cool-core/          #   核心框架（CRUD / sa-token / 缓存 / 密码）
│   ├── cool-db/            #   SQLx 连接池
│   ├── cool-func/          #   分布式函数（Redis pub/sub）
│   ├── cool-file/          #   文件存储驱动
│   ├── cool-micro/         #   微服务脚手架（分布式会话 / 服务鉴权）
│   └── cool-tools/         #   CLI
├── apps/                   # 业务应用（模块 + 微服务 + proto + manifest + migrations）
│   ├── base/               #   登录 / 用户 / 角色 / 部门 / 菜单 / 日志  :8001
│   │   ├── proto/base/v1/  #     自有 gRPC 契约
│   │   ├── manifest/       #     自有配置 config.yaml
│   │   ├── migrations/     #     自有数据库迁移
│   │   └── src/            #     lib（业务） + main（微服务入口）
│   ├── dict/               #   字典  :8002
│   ├── space/              #   文件空间  :8003
│   ├── task/               #   定时任务  :8004
│   ├── demo/               #   CRUD 示范（仅 lib）
│   └── server/             #   单体 all-in-one
└── docs/                   # Mintlify 文档
```

## 分层依赖

依赖方向严格自上而下，禁止反向依赖：

```mermaid
graph TD
    Svc[apps/* 二进制] --> Modules[apps/* 业务模块]
    Svc --> Micro[cool-micro 微服务脚手架]
    Svc --> Core[cool-core]
    Modules --> Core
    Modules --> Proto[cool-proto]
    Modules --> Func[cool-func]
    Modules --> File[cool-file]
    Micro --> Core
    Core --> Db[cool-db]
    Func --> Core
    File --> Core
```

## 部署形态

| 模式 | 说明 |
| --- | --- |
| 单体 | `cool-admin-rust` 一个进程承载全部模块（开发友好） |
| 微服务 | `base/dict/space/task` 各自独立进程，sa-token 分布式会话共享登录态 |

详见 [微服务架构](/guides/microservices)。

## 模块内部结构

每个业务模块遵循统一的三层模式（对齐 cool-admin-go）：

```text
crates/modules/<name>/
├── src/
│   ├── model/        # Model 实现（表名 + 列元信息）
│   ├── service/      # CrudService 实现 + 业务钩子
│   └── handler/      # gRPC Service 实现
└── tests/            # 集成测试
```

<Tip>
  新增模块可用 `cool-tools module <name>` 一键生成骨架。
</Tip>
